## US-MOD-01

Реализован прием событий от B2B через `POST /api/v1/b2b/events` по текущему OpenAPI Moderation. Для совместимости с каноном MOD-1 также добавлен алиас `POST /api/v1/events/product`, но основной контракт остается OpenAPI. Сервис проверяет `X-Service-Key`, сохраняет ключи идемпотентности, создает карточку в `PENDING`, возвращает `EDITED` из `MODERATED`/`BLOCKED`/`IN_REVIEW` в очередь и удаляет карточку по `PRODUCT_DELETED`.

## ADR

Рассматривал три варианта хранения изменений карточки: `json_before + json_after`, только полный `json_after` и `delta`. Выбрал `json_before + json_after`: это занимает больше места, чем один `json_after`, но сильно упрощает диагностику инцидентов и дает модератору понятный снимок "было/стало". `delta` экономит место, но усложняет восстановление полной картины и делает разбор сетевых повторов дороже. Только `json_after` проще всего по БД, но хуже для аудита и объяснения повторной модерации.
